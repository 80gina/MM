# 팀미션 결과보고서

## 1. 문제 정의와 주제 선정

사용자가 하루의 감정을 안전하게 기록하고, 기록 직후 이해하기 쉬운 피드백과 작은 휴식 행동을 받을 수 있도록 **Mindily: AI 감정 일기장 및 맞춤형 힐링 코치**를 제작했다. 상담실처럼 무거운 화면 대신 아이보리 배경, 파스텔 색상, 둥근 카드, 넉넉한 여백을 사용해 개인적인 휴식 공간의 인상을 유지했다.

## 2. 목표 사용자와 해결 방법

대상은 자신의 감정을 글로 정리하고 싶은 초보 사용자다. 홈 → 일기 → AI 감정 분석 → 무드 미터 수정 → 힐링 활동 → 마음 기록의 흐름을 한 화면씩 안내한다. 사용자가 직접 고른 감정과 스트레스는 모델 예측과 구분해 저장한다.

## 3. AI 활용과 기술적 선택

감정 분류에는 AI Hub 감정 데이터로 학습된 공개 `GGARA02/KcELECTRA`를 사용한다. FastAPI가 텍스트를 받아 토큰 길이에 맞춰 분할하고 분류 점수를 평균해 6개 감정 점수와 대표 감정을 반환한다. 모델 버전은 `2eaf89d8d2cbfd902b93e5ec989db2ec103806fb`로 고정했다. 서버는 일기 원문을 저장하지 않으며, 브라우저에는 일기 원문·사용자 감정·스트레스를 저장한다.

현재 구현은 모델 API, 제한된 도구 호출형 Agent, 출처 검색·근거 연결(RAG), 동의 기반 최소 선호 기억을 결합한 MVP다. 일기에서는 `analyze_emotion → recommend_healing → retrieve_grounding` 순서로 실행하고, 대화에서는 휴식 요청에 추천과 근거를 연결한다. 코치 답변은 외부 LLM 키가 없어 결정론적 fallback이며 응답에 생성 방식을 공개한다. 팀미션 기술 요소 중 Agent·RAG·장기기억을 구현했다.

- `python test_feedback.py`: 만족도 점수·동의 거부·SQLite 지속 저장 검증
- `python test_healing.py`: 출처 검색·선호 활동 저장·추천 순서 변경·삭제 검증
- `python test_memory_restart.py`: 별도 프로세스 재시작 후 선호 조회, 해시 토큰, 삭제 및 30일 경과 기록 정리 검증
- `python test_agent.py`: 일기·대화 의도별 도구 호출 순서, 출처, 원문 없는 실행 추적 및 입력 검증
- `python test_packaging.py`: Dockerfile이 서버의 로컬 Python import와 UI를 포함하는지 확인. Docker 이미지 빌드 자체는 미실시.
- 로컬 실제 모델 API `POST /api/agent/coach`: 불안 분류, `analyze_emotion → recommend_healing`, 출처 있는 `1분 호흡하기` 반환 확인
- 임시 HTTPS 주소에서 같은 Agent API와 브라우저 대화·일기 흐름 확인. 브라우저 채팅에는 규칙 기반 응답과 NHS 출처 링크가 표시됨. 이는 내부 합성 문장 점검이며 실제 사용자 피드백은 아님.
- 임시 HTTPS에서 합성 토큰의 선호 저장→조회→삭제→재조회(없음)를 검증함. 합성 기록은 바로 삭제했으며 실제 사용자 기억이나 피드백을 만들지 않음.
- 임시 HTTPS에서 추천 API가 출처 카드 반환, 피드백 API가 동의 거부 시 저장하지 않음을 확인. 감정 정리하기는 합성 문장으로 저장·새로고침 후 재표시를 확인.
- 추천 API에 꽃·나무, 필사, 음악 검색, 취미 카드와 HTTPS 출처 링크가 포함되는지 확인. 위치·맛집 추천은 권한과 최신 영업 정보가 필요해 구현하지 않았다.

### 모델 학습 진행과 결과

공개 `GGARA02/kcelectra-korean-emotion` 모델은 AI Hub 감성대화말뭉치의 발화 텍스트를 사용해 KcELECTRA를 6개 감정으로 5 epoch 파인튜닝한 모델이다. 모델 카드 기준 학습/검증 표본은 51,630/6,641건이며, 별도 테스트 5,135건에서 정확도 86.95%, Macro F1 0.8672가 보고됐다.

제공된 팀 학습 화면에서는 5 epoch 학습 정확도 81.97%, 테스트 정확도 61.80%를 확인했다. 약 20.17%p의 차이가 있으므로 과적합, 데이터 분할, 라벨 불균형과 체크포인트 선택을 추가 점검해야 한다. 데이터 전처리, 분리, 토큰화·정수 인코딩·패딩, 학습 설정과 테스트 해석은 `docs/모델학습보고서.md`에 구분해 기록했다.

데이터셋 전처리 전후 비교와 모델 입력 전처리 전후 비교도 같은 문서에 추가했다. 원본 JSON 정리·라벨 통일·중복 제거·대화 단위 분리는 데이터셋 수준으로, 토큰화·정수 인코딩·128 토큰 길이 제한·패딩·attention mask는 모델 입력 수준으로 구분했다. 전수 집계되지 않은 제외 건수는 추정하지 않고 추후 기록란으로 남겼다.

## 7. 제한사항과 다음 단계

무료 임시 HTTPS 터널과 Agent·근거 연결, 선호 기억의 재시작·만료·삭제는 검증했다. 상시 배포와 5명 실사용자 피드백은 사용자가 제외한 범위다. 외부 LLM 연결, 토큰 분실 운영 대책, 실제 사용자 검증은 후속 운영 항목이다.

이번 보완에서는 만족도 제출 오류를 수정하고 점수 1~5를 SQLite에 저장하도록 바꿨다. 서버 데이터 디스크가 영속적이어야 재시작·배포 후 응답이 유지된다. 선호 활동 기억은 원문 대신 활동 종류만 저장하고 브라우저의 익명 토큰으로 조회·삭제한다. 30일이 지난 선호는 다음 기억 요청 시 삭제하며 추천에 사용하지 않는다. 토큰을 잃은 사용자가 즉시 이전 기록을 삭제하는 복구 수단과 장기간 운영 검증은 아직 남아 있다.

### 확장 기능 우선순위

감정에 따른 꽃·나무·향수, 필사할 책·시집·명언, 음악·영상·취미·수업 추천을 먼저 추가한다. 이후 사용자가 허용한 경우에만 러닝 장소와 근처 힐링 장소·맛집을 조회한다. 위치 정보는 일회성으로 사용하고 저장하지 않으며, 추천 콘텐츠는 출처와 저작권 상태를 함께 표시한다.

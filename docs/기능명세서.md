상태: 전체 목표 명세. 모델 API, 무드 수정 저장, 제한된 도구 호출형 코치, 감정 정리 3문항, 동의 기반 선호 기억은 구현했으며 나머지 상세 상태는 INTEGRATION_REPORT.md와 시연보고서를 확인합니다.

## 감정 표현
- 코랄: 쾌적함 낮음·활력 높음 — 불안, 긴장.
- 옐로: 쾌적함 높음·활력 높음 — 신남, 설렘.
- 블루: 쾌적함 낮음·활력 낮음 — 지침, 슬픔.
- 세이지: 쾌적함 높음·활력 낮음 — 차분함, 편안함.
- 색과 텍스트·아이콘을 함께 사용한다. 사용자가 최종 선택한다.
- 기쁨을 무조건 고활력, 불안을 무조건 특정 좌표로 고정하지 않는다.
- 평온·중립 등 모델 출력에 없는 감정도 직접 선택할 수 있다.

## 공통 디자인과 상태
아이보리 배경, 네이비 본문, 라벤더 주요 버튼, 둥근 카드, 충분한 여백, 식물·창가·구름 캐릭터를 유지한다.
iOS·Android 모바일 브라우저와 데스크톱에서 확인한다. 네이티브 앱 설치·스토어 출시는 현재 확정 범위가 아니다.
큰 글자, 터치 영역, 색 대비, 모션 줄이기, 화면 낭독용 이름을 확인한다.
모든 데이터 화면에 최초 사용·로딩·성공·오류·기록 없음 상태를 준비한다.
UI 예시 데이터와 실제 사용자 기록은 구분한다.
# 확장 기능 제안

아래 기능은 기본 감정 분석 흐름을 해치지 않으면서 감정별 회복 행동을 넓히는 2단계 기능이다. 모든 추천은 의료적 처방이 아니라 선택 가능한 콘텐츠로 표시한다.

| ID | 기능 | 입력 | 결과 | 개인정보·안전 기준 |
|---|---|---|---|---|
| F20 | 감정별 꽃·향 추천 | 대표 감정 | 감정별 추천 꽃(꽃말)과 추천 향을 분석 화면에 표시 (`comfort_knowledge.py`) | 효능을 주장하지 않음. 알레르기 주의와 무향 대안을 항상 함께 표시 |
| F21 | 필사·인용 콘텐츠 | 감정, 길이, 난이도 | 공개 도서 탐색 카드, 짧은 필사 안내, 감정별 **저작권 만료 인용구** 표시 | 전문·긴 원문 금지. **저작권이 살아 있는 현대 가요 가사·생존 작가 글은 싣지 않음**. 출처와 만료 근거를 화면에 함께 표시 |
| F22 | 음악·영상·취미·수업 추천 | 감정, 시간, 콘텐츠 선호 | 수동 음악 검색·10분 선 그리기 카드 구현 | 플랫폼 링크만 저장, 자동 재생 금지 |
| F23 | 러닝 장소 추천 | 위치 선택, 거리, 운동 강도 | 안전한 산책·러닝 코스 | 위치는 일회성 조회, 서버 저장 금지 |
| F24 | 근처 힐링 장소·맛집 | 사용자가 허용한 위치, 영업 상태 | 공원·도서관·카페·식당 카드 | 정확한 위치 대신 동 단위 표시, 지도 API 약관 준수 |
| F25 | 추천 피드백 | 추천 카드의 도움됨/관심없음 | 다음 추천의 개인화 | 사용자가 언제든 기록 삭제 가능 |

### 추천 파이프라인

`KcELECTRA 감정 → 무드 미터 좌표 → 선호·시간 필터 → (선택 시) 위치·영업 정보 조회 → 추천 카드 → 도움됨 피드백`

초기에는 고정된 큐레이션 데이터로 시작하고, 이후 RAG로 출처가 있는 콘텐츠를 검색한다. 위치 검색은 브라우저 권한을 받은 순간에만 실행하며 좌표를 장기기억에 넣지 않는다.

### Agent 도구 계약

| 도구 | 책임 | 실패 시 동작 |
|---|---|---|
| `analyze_emotion` | KcELECTRA 분류와 스트레스 입력을 감정 좌표로 정리 | 입력 오류를 사용자에게 안내하고 원문을 보존 |
| `recommend_healing` | 감정·시간·선호에 맞춰 콘텐츠와 장소 추천 | 위치 권한이 없으면 비위치 추천으로 대체 |
| `save_user_feedback` | 추천 도움됨과 사용자 의견을 익명 집계 | 동의가 없으면 저장하지 않음 |

추천 기능 중 현재 구현된 F20 일부·F21·F22 일부는 `recommend_healing` 결과 카드로 연결한다. F23·F24 위치 기능은 권한·지도 API·영업 정보 검증을 마친 뒤 추가한다. 추천 평가 F25는 `save_user_feedback`에 연결한다. 모든 대화 흐름은 먼저 `analyze_emotion` 결과를 읽고 다음 도구를 선택한다.

현재 MVP에서 `/api/agent/coach`는 일기 요청 시 분석과 추천을 순서대로 실행한다. 대화에서 ‘추천·쉬다·호흡’ 같은 휴식 의도를 감지하면 최근 일기의 감정이 있을 때만 이를 참고해 추천하고, 없으면 감정을 추정해 단정하지 않는다. 감정을 이야기하는 대화는 모델 분석을 실행한다. 실행 추적에는 도구 이름만 포함하며 일기 원문은 넣지 않는다. `save_user_feedback`은 종료 설문에서 별도로 호출한다. 코치 응답은 규칙 기반 문장이고 LLM 기반 RAG는 아직 구현하지 않았다.

## 1. 적용한 모델

| 항목 | 값 |
|---|---|
| 모델 | `GGARA02/kcelectra-korean-emotion` |
| 리비전 | `2eaf89d8d2cbfd902b93e5ec989db2ec103806fb` (고정) |
| 기반 | KcELECTRA — 한국어 구어체 특화 ELECTRA |
| 출력 라벨 | 불안 · 슬픔 · 분노 · 기쁨 · 상처 · 당황 (6종) |
| 추론 방식 | 128토큰 청크 분할 + 토큰 수 가중 평균 |
| 실행 환경 | CPU (Hugging Face Space CPU basic) |

### 모델 사양 (`config.json` 실측, 2026-09-19 Hub 조회)

| 항목 | 값 |
|---|---|
| 아키텍처 | `ElectraForSequenceClassification` |
| 레이어 / 은닉 차원 / 어텐션 헤드 | 12 / 768 / 12 |
| 어휘 크기 | 54,343 |
| 최대 위치 임베딩 | 512 |
| 문제 유형 | `single_label_classification` |
| 라벨 순서 | 0 분노 · 1 기쁨 · 2 불안 · 3 당황 · 4 슬픔 · 5 상처 |
| 토크나이저 | `BertTokenizer` |

**입력을 512가 아닌 128토큰으로 자르는 이유**: 모델이 학습된 길이에 맞추기 위함입니다. 128을 넘는 글은 잘라내지 않고 **여러 청크로 나눠 각각 추론한 뒤 토큰 수로 가중 평균**하므로, 긴 일기도 전부 반영됩니다.

**리비전을 고정한 이유**: 모델 소유자가 가중치를 바꾸면 같은 문장이 다른 결과를 내게 됩니다. 리비전을 박아두면 제3자가 같은 결과를 재현할 수 있고, 보고서의 수치가 검증 가능해집니다.

## 2. 실제 분류 결과

`evidence/api-check.json` (2026-09-19 11:15 UTC, 실제 API 호출)

| 입력 | HTTP | 최상위 감정 | 점수 | 청크 수 |
|---|---|---|---|---|
| 걱정 문장 (`내일 발표를…`) | 200 | **불안** | **0.941** | 1 |
| 긴 글 (128토큰 초과) | 200 | **불안** | 0.437 | **2** |
| 빈 입력 | 422 | — | — | 입력 검증으로 차단 |
| 범위 밖 스트레스 값 | 422 | — | — | 입력 검증으로 차단 |

### 읽는 법

**0.941은 "불안이 94%"라는 뜻이 아닙니다.** 6개 라벨에 대한 softmax 확률 분포의 최댓값이며, 화면에도 "분류 점수는 실제 감정 비율이 아니에요. 최종 마음은 직접 선택해주세요."라고 명시합니다.

**긴 글에서 점수가 0.437로 낮아진 것은 오작동이 아닙니다.** 긴 글에는 여러 감정이 섞이므로 청크별 결과를 토큰 수로 가중 평균하면 분포가 평평해집니다. 오히려 단일 감정으로 단정하지 않는다는 점에서 의도한 동작입니다.

모델이 **불안**이라고 해도 사용자가 무드 미터에서 **편안한**으로 바꿀 수 있고, 두 값은 **덮어쓰지 않고 별도 필드로** 저장됩니다. 감정의 최종 판단 주체는 사용자라는 설계를 데이터 구조로 보장한 것입니다.

### 4.2 처음부터 드러난 두 가지 문제

| 문제 | 구체적 수치 | 의미 |
|---|---|---|
| **`상처` 라벨 신규 표본 0건** | 6개 중 1개 라벨이 학습 데이터에 없음 | 추가 학습 시 기존 `상처` 분류 능력이 손상될 위험 (catastrophic forgetting) |
| **극심한 클래스 불균형** | 학습셋 기쁨 330,711 vs 불안 16,233 → **약 20:1** | 다수 클래스로 쏠리는 모델이 되기 쉬움 |

데이터 분리는 JSON 파일 경로의 SHA-1 해시 기준 80/10/10 **그룹 분리**로 수행했습니다. 같은 대화의 발화가 학습셋과 평가셋에 동시에 들어가는 누수를 막기 위함입니다.

### 4.5 판단: 채택하지 않음

5개 클래스 무작위 추측의 기대 정확도가 0.20인데 측정값은 **0.26**입니다. 즉 **무작위보다 의미 있게 낫다고 말할 수 없는 수준**입니다.

| 판단 근거 | 내용 |
|---|---|
| 성능 | 공개 모델(걱정 문장 0.941)보다 명백히 낮다 |
| 표본 | 학습 100건 · 1에폭은 84만 건 데이터를 대표하지 못한다 |
| 구조적 결함 | `상처` 라벨 미포함으로 6종 분류 체계가 깨진다 |
| 불균형 | 20:1 불균형을 처리하지 않은 상태 |

따라서 **서비스에는 공개 모델을 그대로 적용**하고, 파일럿 결과는 지우지 않고 기록으로 남겼습니다.

> 이 수치는 "team_motion 데이터가 쓸모없다"는 뜻이 아니라, **CPU 100건 1에폭 조건에서는 개선을 확인할 수 없었다**는 뜻입니다. 데이터의 가능성과 실험 조건의 한계는 구분해서 읽어야 합니다.

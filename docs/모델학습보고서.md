# KcELECTRA 감정 분류 모델 학습 보고서

## 1. 보고 범위

Mindily는 AI Hub 감성대화말뭉치로 파인튜닝된 공개 모델 `GGARA02/kcelectra-korean-emotion`을 감정 분류에 사용한다. 이 문서는 공개 모델 카드의 학습 정보와 팀이 제공한 5 epoch 학습 로그를 구분해 기록한다.

- 공개 모델 출처: https://huggingface.co/GGARA02/kcelectra-korean-emotion
- 사용 revision: `2eaf89d8d2cbfd902b93e5ec989db2ec103806fb`
- 분류 감정: 분노, 기쁨, 불안, 당황, 슬픔, 상처
- 구조: `ElectraForSequenceClassification`

> 주의: 현재 저장소에서 공개 모델을 새로 학습한 것은 아니다. 공개 모델을 내려받아 추론 API에 연결했다. 아래의 별도 학습 로그는 사용자가 제공한 실행 화면을 근거로 기록했으며, 원본 학습 코드·분할 인덱스·전체 로그가 확보되기 전에는 완전한 재현 결과로 보지 않는다.

## 2. 데이터셋 전처리

공개 모델 카드에 따르면 AI Hub 감성대화말뭉치에서 한 사람의 `사람문장1~3`을 이어 붙여 하나의 입력 문장으로 만들고, 메타데이터를 제외한 발화 텍스트만 사용했다.

권장 전처리 순서는 다음과 같다.

1. JSON에서 사람 발화와 대분류 감정 라벨을 읽는다.
2. 빈 문자열, 라벨 누락, 손상된 JSON을 제외한다.
3. 같은 사람의 발화 1~3을 순서대로 결합한다.
4. 라벨을 0~5 정수로 변환한다.
5. 원문·개인정보는 GitHub에 업로드하지 않고 전처리 통계만 저장한다.

라벨 정수 매핑은 모델 설정을 기준으로 한다.

| 정수 | 감정 |
|---:|---|
| 0 | 분노 |
| 1 | 기쁨 |
| 2 | 불안 |
| 3 | 당황 |
| 4 | 슬픔 |
| 5 | 상처 |

로컬 `team_motion` 데이터는 `SpeakerEmotionCategory`, `VerifyEmotionCategory` 등 별도 라벨 구조를 포함한다. 공개 모델의 6개 감정과 자동으로 동일시하지 않고, 라벨 가이드를 확인한 후 별도의 변환표와 제외 기준을 만들어야 한다.

## 3. 데이터 분리

공개 모델 카드에 기록된 데이터 수는 다음과 같다.

| 구분 | 표본 수 | 용도 |
|---|---:|---|
| 학습 | 51,630 | 가중치 업데이트 |
| 검증 | 6,641 | 학습 중 성능 확인과 모델 선택 |
| 테스트 | 5,135 | 최종 일반화 성능 평가 |

팀 제공 학습 화면에는 학습 932 batch, 테스트 311 batch가 표시된다. 배치 수 기준으로는 약 75:25이지만, 배치 크기와 마지막 배치 표본 수가 없어 실제 표본 비율로 확정할 수 없다. 최종 제출 전 아래 값을 학습 코드에서 확인해 채운다.

- 전체 표본 수: ______
- 학습/검증/테스트 표본 수: ______ / ______ / ______
- 분리 비율: ______
- 난수 seed: ______
- 계층적 분할 여부: ______
- 동일 대화가 서로 다른 분할에 섞이지 않았는지: ______

감정별 표본 불균형을 줄이기 위해 라벨 비율을 유지하는 계층적 분할을 사용하고, 같은 대화에 속한 문장은 하나의 분할에만 포함하는 그룹 분할을 권장한다.

## 4. 토큰화·정수 인코딩·패딩

`AutoTokenizer`가 한국어 텍스트를 KcELECTRA 어휘에 맞는 하위 토큰으로 나눈 뒤 각 토큰을 정수 ID로 바꾼다. 모델 입력은 `input_ids`와 실제 토큰 위치를 구분하는 `attention_mask`로 구성한다.

- 최대 시퀀스 길이: 128
- 특수 토큰: 문장 시작·종료 토큰을 토크나이저가 자동 추가
- 정수 인코딩: 토큰을 모델 vocabulary ID로 변환
- 잘림: 128 토큰을 넘는 입력은 학습 조건에 맞춰 자름
- 패딩: 배치 안의 길이를 맞추고 패딩 위치는 `attention_mask=0`으로 처리

현재 서비스 추론 코드는 1,000자 이내의 긴 일기를 128 토큰 단위로 나누고, 각 청크의 감정 점수를 토큰 수에 따라 가중 평균한다. 이는 한 발화만 입력한 공개 모델의 평가 조건과 다르므로 서비스 성능은 별도 사용자 데이터로 검증해야 한다.

## 5. 모델 학습

공개 모델 카드의 학습 설정은 다음과 같다.

| 항목 | 설정 |
|---|---|
| 베이스 모델 | `beomi/KcELECTRA-base-v2022` |
| epoch | 5 |
| 최대 길이 | 128 |
| batch size | 학습 32 / 평가 64 |
| optimizer | AdamW, weight decay 0.01 |
| learning rate | encoder `2e-5`, classifier head `1e-4` |
| scheduler | 10% linear warmup 후 linear decay |
| gradient clipping | 1.0 |
| seed | 42 |

팀 제공 화면에서 확인된 5 epoch 마지막 로그는 다음과 같다.

| 지표 | 결과 |
|---|---:|
| 학습 batch | 932/932 |
| 테스트 batch | 311/311 |
| 5 epoch 학습 정확도 | 0.8196519582 (81.97%) |
| 5 epoch 테스트 정확도 | 0.6179922247 (61.80%) |
| 학습-테스트 정확도 차이 | 약 20.17%p |

중간 batch의 학습 정확도는 약 79.62~82.81%, loss는 약 0.424~0.759로 표시됐다. 한 epoch의 화면만으로 수렴 여부를 판단할 수 없으므로 epoch별 train/validation loss와 macro F1을 함께 저장해야 한다.

## 6. 결과물 테스트

공개 모델 카드가 AI Hub 테스트셋 5,135건에서 보고한 결과는 정확도 86.95%, Macro F1 0.8672, Top-2 정확도 93.96%다. 팀 제공 학습 로그의 테스트 정확도 61.80%와는 평가 데이터·전처리·분할·체크포인트가 다를 수 있으므로 직접 비교해서 우열을 단정하지 않는다.

Mindily 서비스에서는 다음 API 검증을 완료했다.

- 정상 감정 문장: HTTP 200, 6개 감정 점수 반환
- 빈 입력: HTTP 422
- 스트레스 범위 초과: HTTP 422
- 긴 일기: 2개 이상 청크로 나눠 분석
- 브라우저: 모델 결과 표시, 사용자 감정 수정, 새로고침 후 기록 유지

## 7. 결과 해석과 보완 제언

팀 로그의 학습 정확도와 테스트 정확도 차이 20.17%p는 과적합, 데이터 분포 차이, 중복 대화 분리, 라벨 불균형 또는 최종 체크포인트 선택 문제를 점검해야 한다는 신호다. 다음 순서로 보완한다.

1. 대화 ID 단위로 train/validation/test를 다시 분리해 데이터 누수를 막는다.
2. 감정별 precision, recall, F1과 confusion matrix를 저장한다.
3. validation macro F1이 가장 높은 체크포인트를 사용한다.
4. class weight 또는 weighted sampler의 필요성을 라벨 분포로 판단한다.
5. 동일 seed로 재학습하고 학습 설정·패키지 버전·커밋을 기록한다.
6. 실제 일기 문장과 AI Hub 테스트 문장의 분포 차이를 별도 오류 분석한다.

현재 결과는 감정 신호를 제공하는 보조 모델로 사용할 수 있으나 심리 진단 정확도로 해석해서는 안 된다. 앱에서는 모델 예측 뒤에 사용자가 직접 감정을 확인·수정하도록 유지한다.

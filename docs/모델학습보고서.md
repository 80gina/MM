# KcELECTRA 감정 분류 모델 학습 보고서

## 1. 보고 범위

Mindily는 AI Hub 감성대화말뭉치로 파인튜닝된 공개 모델 `GGARA02/kcelectra-korean-emotion`을 감정 분류에 사용한다. 이 문서는 공개 모델 카드의 학습 정보와 팀이 제공한 5 epoch 학습 로그를 구분해 기록한다.

- 공개 모델 출처: https://huggingface.co/GGARA02/kcelectra-korean-emotion
- 사용 revision: `2eaf89d8d2cbfd902b93e5ec989db2ec103806fb`
- 분류 감정: 분노, 기쁨, 불안, 당황, 슬픔, 상처
- 구조: `ElectraForSequenceClassification`

> 주의: 현재 저장소에서 공개 모델을 새로 학습한 것은 아니다. 공개 모델을 내려받아 추론 API에 연결했다. 아래의 별도 학습 로그는 사용자가 제공한 실행 화면을 근거로 기록했으며, 원본 학습 코드·분할 인덱스·전체 로그가 확보되기 전에는 완전한 재현 결과로 보지 않는다.

## 2. 데이터셋 전처리

공개 모델 카드에 따르면 AI Hub 감성대화말뭉치에서 한 사람의 `사람문장1~3`을 이어 붙여 하나의 입력 문장으로 만들고, 메타데이터를 제외한 발화 텍스트만 사용했다.

권장 전처리 순서는 다음과 같다.

1. JSON에서 사람 발화와 대분류 감정 라벨을 읽는다.
2. 빈 문자열, 라벨 누락, 손상된 JSON을 제외한다.
3. 같은 사람의 발화 1~3을 순서대로 결합한다.
4. 라벨을 0~5 정수로 변환한다.
5. 원문·개인정보는 GitHub에 업로드하지 않고 전처리 통계만 저장한다.

라벨 정수 매핑은 모델 설정을 기준으로 한다.

| 정수 | 감정 |
|---:|---|
| 0 | 분노 |
| 1 | 기쁨 |
| 2 | 불안 |
| 3 | 당황 |
| 4 | 슬픔 |
| 5 | 상처 |

로컬 `team_motion` 데이터는 `SpeakerEmotionCategory`, `VerifyEmotionCategory` 등 별도 라벨 구조를 포함한다. 공개 모델의 6개 감정과 자동으로 동일시하지 않고, 라벨 가이드를 확인한 후 별도의 변환표와 제외 기준을 만들어야 한다.

### 데이터셋 전처리 전후 비교표

여기서 데이터셋 전처리는 JSON 파일을 학습 가능한 표 형태로 정리하는 과정이다. 아래의 “전”은 원본 구조, “후”는 학습용 데이터가 갖춰야 할 목표 구조다.

| 비교 항목 | 전처리 전 | 전처리 후 | 처리 이유 | 결과물에 미치는 영향 |
|---|---|---|---|---|
| 저장 구조 | JSON마다 `Conversation` 배열과 화자·음성·검증 메타데이터가 함께 있음 | 한 행에 `text`, `label`, `conversation_id`만 남김 | 모델 학습에 필요한 정보만 일관된 표로 만들기 위해 | 데이터 로더가 단순해지고 불필요한 개인정보 사용 위험이 감소 |
| 입력 문장 | 한 사람의 문장이 `사람문장1~3`처럼 분리될 수 있음 | 같은 사람의 연속 발화를 순서대로 결합 | 한 문장만으로 부족한 감정 문맥을 보존하기 위해 | 감정 단서가 늘어나지만 입력이 너무 길면 잘릴 수 있음 |
| 빈 값 | 빈 문장·공백·누락 라벨이 포함될 수 있음 | 공백 정리 후 빈 문장과 라벨 누락 행 제외 | 정답이 없는 표본은 손실 계산이 불가능하기 때문에 | 학습 오류와 무의미한 입력을 줄임. 제외 건수 기록이 필요함 |
| 중복 | 압축 파일과 해제 파일, 반복 대화가 겹칠 가능성 | `conversation_id`와 정규화 문장으로 중복 검사 | 같은 문장이 학습·테스트에 동시에 들어가는 누수를 막기 위해 | 테스트 점수가 실제보다 높아지는 위험 감소 |
| 감정 라벨 | `SpeakerEmotionCategory`, `VerifyEmotionCategory` 등 여러 필드와 서로 다른 값 | 검증 라벨을 우선하고, 확정된 6개 감정만 정수 0~5로 변환 | 입력 하나에 일관된 정답 하나를 연결하기 위해 | 라벨 노이즈 감소. 억지 매핑은 특정 감정 오분류를 늘릴 수 있음 |
| 중립·미정 라벨 | `중립`, `없음`, 숫자 코드 등이 관찰됨 | 정의가 확인되지 않은 값은 제외 또는 별도 클래스로 보류 | 중립을 기쁨 등으로 임의 변환하면 정답이 왜곡되기 때문에 | 6개 감정 분류의 신뢰도는 높아지지만 사용 가능한 표본 수는 감소 |
| 개인정보·메타데이터 | 화자·음성·파일 관련 필드 포함 | 학습 입력에서 제거하고 통계만 보관 | 감정 분류에 필요하지 않은 정보의 사용을 최소화하기 위해 | 개인정보 위험과 불필요한 편향 가능성 감소 |
| 데이터 분리 | 파일 순서 또는 무작위 행 단위 분리 가능 | 대화 ID 단위 그룹 분리와 감정별 계층화 적용 | 같은 대화가 여러 분할에 섞이지 않게 하기 위해 | 일반화 성능을 더 정직하게 측정할 수 있음 |

## 3. 데이터 분리

공개 모델 카드에 기록된 데이터 수는 다음과 같다.

| 구분 | 표본 수 | 용도 |
|---|---:|---|
| 학습 | 51,630 | 가중치 업데이트 |
| 검증 | 6,641 | 학습 중 성능 확인과 모델 선택 |
| 테스트 | 5,135 | 최종 일반화 성능 평가 |

팀 제공 학습 화면에는 학습 932 batch, 테스트 311 batch가 표시된다. 배치 수 기준으로는 약 75:25이지만, 배치 크기와 마지막 배치 표본 수가 없어 실제 표본 비율로 확정할 수 없다. 최종 제출 전 아래 값을 학습 코드에서 확인해 채운다.

- 전체 표본 수: ______
- 학습/검증/테스트 표본 수: ______ / ______ / ______
- 분리 비율: ______
- 난수 seed: ______
- 계층적 분할 여부: ______
- 동일 대화가 서로 다른 분할에 섞이지 않았는지: ______

감정별 표본 불균형을 줄이기 위해 라벨 비율을 유지하는 계층적 분할을 사용하고, 같은 대화에 속한 문장은 하나의 분할에만 포함하는 그룹 분할을 권장한다.

## 4. 토큰화·정수 인코딩·패딩

`AutoTokenizer`가 한국어 텍스트를 KcELECTRA 어휘에 맞는 하위 토큰으로 나눈 뒤 각 토큰을 정수 ID로 바꾼다. 모델 입력은 `input_ids`와 실제 토큰 위치를 구분하는 `attention_mask`로 구성한다.

- 최대 시퀀스 길이: 128
- 특수 토큰: 문장 시작·종료 토큰을 토크나이저가 자동 추가
- 정수 인코딩: 토큰을 모델 vocabulary ID로 변환
- 잘림: 128 토큰을 넘는 입력은 학습 조건에 맞춰 자름
- 패딩: 배치 안의 길이를 맞추고 패딩 위치는 `attention_mask=0`으로 처리

현재 서비스 추론 코드는 1,000자 이내의 긴 일기를 128 토큰 단위로 나누고, 각 청크의 감정 점수를 토큰 수에 따라 가중 평균한다. 이는 한 발화만 입력한 공개 모델의 평가 조건과 다르므로 서비스 성능은 별도 사용자 데이터로 검증해야 한다.

### 모델 입력 전처리 전후 비교표

이 단계의 데이터 전처리는 정리된 한국어 문장을 신경망이 계산할 수 있는 숫자 배열로 바꾸는 과정이다. 아래 예시는 개인정보가 없는 가상 문장이다.

예시 입력: `내일 발표가 걱정돼요.`

| 단계 | 전처리 전 | 전처리 후 | 이렇게 처리한 이유 | 결과물에 미치는 영향 |
|---|---|---|---|---|
| 공백·문자 정리 | 앞뒤 공백이나 반복 공백이 있을 수 있음 | 앞뒤 공백 제거, 의미 있는 문장은 유지 | 같은 문장이 불필요하게 다른 형태가 되는 것을 줄이기 위해 | 토큰 길이와 중복 판정이 안정됨 |
| 토큰화 | 사람이 읽는 한국어 문장 | KcELECTRA 토크나이저의 하위 토큰 목록 | 모델은 문자열을 직접 계산할 수 없기 때문에 | 한국어 어미·조사·미등록 단어를 부분 단위로 처리 가능 |
| 정수 인코딩 | `내일`, `발표`, `걱정` 등의 토큰 | vocabulary에 대응하는 `input_ids` 정수 배열 | 임베딩 행렬에서 각 토큰 표현을 찾기 위해 | 잘못된 토크나이저를 쓰면 사전학습 표현을 활용할 수 없음 |
| 특수 토큰 | 일반 문장만 존재 | 문장 시작·종료를 나타내는 특수 ID 추가 | ELECTRA가 문장 경계를 구분하도록 하기 위해 | 분류용 문장 표현을 안정적으로 생성 |
| 길이 제한 | 문장마다 길이가 다르고 긴 일기도 존재 | 최대 128 토큰, 초과 입력은 청크 분할 | 공개 모델의 학습 조건과 메모리 한도에 맞추기 위해 | 앞부분만 잘라 정보가 사라지는 문제를 줄이지만 여러 청크 평균에 따른 의미 희석 가능 |
| 패딩 | 문장 길이가 서로 다름 | 같은 배치의 길이를 패딩 ID로 맞춤 | GPU·CPU가 고정 크기 행렬로 묶어 처리하기 위해 | 배치 연산이 가능해지고 처리 속도가 향상 |
| Attention mask | 실제 토큰과 패딩 구분 없음 | 실제 토큰 1, 패딩 0 | 패딩을 실제 문장으로 계산하지 않게 하기 위해 | 패딩 때문에 감정 점수가 왜곡되는 것을 방지 |
| 라벨 인코딩 | `불안`, `기쁨` 같은 문자열 | `불안=2`, `기쁨=1` 등의 정수 | 분류 손실 함수가 정답 클래스를 계산하도록 하기 위해 | 매핑 순서가 모델 설정과 다르면 모든 평가 결과가 잘못됨 |

실제 토큰 ID는 tokenizer vocabulary와 버전에 따라 달라지므로 보고서에 임의 숫자를 적지 않는다. 재현 시에는 사용 revision, `input_ids` 길이, `attention_mask` 합계만 개인정보 없이 증빙으로 남긴다.

### 전처리 선택이 최종 결과에 미친 영향

1. **6개 라벨 통일**은 모델 출력과 앱 UI를 일치시켰다. 반면 중립이나 복합 감정은 표현하지 못하므로 사용자가 무드 미터에서 결과를 수정하게 했다.
2. **최대 128 토큰**은 공개 학습 조건을 유지해 추론의 일관성을 높였다. 긴 일기는 여러 조각으로 나뉘어 문장 전체 관계를 한 번에 읽지 못한다.
3. **토큰 가중 평균**은 짧은 마지막 청크가 결과를 과도하게 좌우하는 것을 줄였다. 다만 중요한 한 문장이 긴 글 속에서 희석될 수 있다.
4. **메타데이터 제거**는 개인정보와 편향 위험을 줄였다. 화자 연령·성별 같은 정보가 사라져 집단별 성능 차이를 모델 입력만으로 보정할 수는 없다.
5. **대화 단위 분리**를 적용하면 테스트 점수가 낮아질 수 있지만, 실제 새 사용자에게 적용할 때의 성능을 더 정확히 보여준다.
6. **라벨 미확정 표본 보류**는 학습량을 줄이지만 잘못된 정답으로 학습하는 위험을 낮춘다.

## 5. 모델 학습

공개 모델 카드의 학습 설정은 다음과 같다.

| 항목 | 설정 |
|---|---|
| 베이스 모델 | `beomi/KcELECTRA-base-v2022` |
| epoch | 5 |
| 최대 길이 | 128 |
| batch size | 학습 32 / 평가 64 |
| optimizer | AdamW, weight decay 0.01 |
| learning rate | encoder `2e-5`, classifier head `1e-4` |
| scheduler | 10% linear warmup 후 linear decay |
| gradient clipping | 1.0 |
| seed | 42 |

팀 제공 화면에서 확인된 5 epoch 마지막 로그는 다음과 같다.

| 지표 | 결과 |
|---|---:|
| 학습 batch | 932/932 |
| 테스트 batch | 311/311 |
| 5 epoch 학습 정확도 | 0.8196519582 (81.97%) |
| 5 epoch 테스트 정확도 | 0.6179922247 (61.80%) |
| 학습-테스트 정확도 차이 | 약 20.17%p |

중간 batch의 학습 정확도는 약 79.62~82.81%, loss는 약 0.424~0.759로 표시됐다. 한 epoch의 화면만으로 수렴 여부를 판단할 수 없으므로 epoch별 train/validation loss와 macro F1을 함께 저장해야 한다.

## 6. 결과물 테스트

공개 모델 카드가 AI Hub 테스트셋 5,135건에서 보고한 결과는 정확도 86.95%, Macro F1 0.8672, Top-2 정확도 93.96%다. 팀 제공 학습 로그의 테스트 정확도 61.80%와는 평가 데이터·전처리·분할·체크포인트가 다를 수 있으므로 직접 비교해서 우열을 단정하지 않는다.

Mindily 서비스에서는 다음 API 검증을 완료했다.

- 정상 감정 문장: HTTP 200, 6개 감정 점수 반환
- 빈 입력: HTTP 422
- 스트레스 범위 초과: HTTP 422
- 긴 일기: 2개 이상 청크로 나눠 분석
- 브라우저: 모델 결과 표시, 사용자 감정 수정, 새로고침 후 기록 유지

## 7. 결과 해석과 보완 제언

팀 로그의 학습 정확도와 테스트 정확도 차이 20.17%p는 과적합, 데이터 분포 차이, 중복 대화 분리, 라벨 불균형 또는 최종 체크포인트 선택 문제를 점검해야 한다는 신호다. 다음 순서로 보완한다.

1. 대화 ID 단위로 train/validation/test를 다시 분리해 데이터 누수를 막는다.
2. 감정별 precision, recall, F1과 confusion matrix를 저장한다.
3. validation macro F1이 가장 높은 체크포인트를 사용한다.
4. class weight 또는 weighted sampler의 필요성을 라벨 분포로 판단한다.
5. 동일 seed로 재학습하고 학습 설정·패키지 버전·커밋을 기록한다.
6. 실제 일기 문장과 AI Hub 테스트 문장의 분포 차이를 별도 오류 분석한다.

현재 결과는 감정 신호를 제공하는 보조 모델로 사용할 수 있으나 심리 진단 정확도로 해석해서는 안 된다. 앱에서는 모델 예측 뒤에 사용자가 직접 감정을 확인·수정하도록 유지한다.

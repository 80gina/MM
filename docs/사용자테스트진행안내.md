# 실제 사용자 5명 테스트 진행 안내

담당: 팀원 3. 이 문서는 진행용 안내이며 실제 참여·동의·평가 결과를 대신하지 않는다. 참가자마다 [기록지](사용자테스트기록지.md)의 U01~U05를 사용한다. 이름·연락처·일기 원문은 GitHub에 올리지 않는다.

## 테스트 직전

1. 팀원 2가 https://yellowmug-mindily.hf.space/api/health 의 `ready`를 확인한다. 절전 중이면 먼저 열어 깨워 둔다. (인터넷이 막히는 환경이면 예비로 같은 와이파이 주소를 쓴다.)
2. 진행자는 휴대폰 **모바일 데이터**로 첫 화면, 가상 문장 분석, 종료 설문 열기를 확인한다. 개발자 자체 점검은 5명 응답에 포함하지 않는다.
3. 팀원 3이 참가자에게 의료 진단이 아닌 시연 앱이며, 일기 문장이 모델 서버로 전송되고 본인 브라우저에 기록이 남는다고 설명한다. 실제 개인 이야기를 쓰지 않아도 된다.
4. 테스트 참여와 앱 내 익명 만족도 제출은 각각 선택 사항임을 안내한다. 점수를 제출하지 않아도 테스트를 중단하거나 설문을 닫을 수 있다.

## 참가자에게 전달할 문구 초안

> Mindily 모바일 감정 일기 앱을 약 5분간 사용해 주세요. 테스트 주소: **https://yellowmug-mindily.hf.space** (홈 화면에 추가하면 앱처럼 열립니다). 실제 개인 일기 대신 `내일 발표를 잘할 수 있을지 걱정돼요.`를 입력하고 스트레스 3을 선택해 주세요. 결과를 읽고 감정을 직접 고른 다음 휴식 활동 하나를 사용해 보세요. 마지막에 **오늘 사용을 마쳤어요 · 만족도 남기기**에서 만족도 1~5점을 선택할 수 있습니다. 제출은 동의할 때만 해 주세요. 이 앱은 의료 진단 도구가 아닙니다. 주소는 테스트 이후에도 그대로 열립니다.

이 문구는 팀원 3이 참가자에게 직접 전달한다. 앱이나 이 저장소에서 자동 발송하지 않는다.

## 진행자 기록 순서

1. 참가자에게 U01~U05 중 아직 쓰지 않은 코드를 부여한다. 실제 인물과 코드를 연결해야 한다면 팀 내부 비공개 장소에서만 관리한다.
2. 참가자가 직접 사용하도록 하고, 진행자는 화면 조작을 대신하지 않는다. 오류가 나면 시간·기기·재현 단계만 적고 일기 원문은 적지 않는다.
3. 앱 설문 완료 여부를 확인한 뒤 이해도·공감도·추천 유용성·접근성 네 점수를 **별도로** 묻고 기록지에 쓴다.
4. 참가자에게 개선점을 한 가지 묻는다. 원문 인용이 민감하면 요약만 기록한다.
5. 5명 완료 후 `python feedback_summary.py`로 서버의 앱 만족도 응답 수·평균을 확인하고, 기록지의 **실제 완료 인원**과 따로 보고한다. 한 사람이 여러 번 제출할 수 있다.
6. 자주 나온 문제를 우선순위로 정해 수정하고, 같은 시나리오로 재확인한다. 개선 전·후 화면, 날짜, 커밋 링크를 [피드백 기록](피드백기록.md)에 남긴다.

브라우저 탭을 완전히 닫은 후에는 웹페이지가 설문창을 띄울 수 없다. 따라서 참가자가 앱을 떠나기 **전** 종료 버튼으로 설문을 열도록 안내한다. 답변을 강제하거나 실제 응답을 예시 데이터로 채우지 않는다.

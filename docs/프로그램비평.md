# Mindily 프로그램 비평 및 향후 방향

## 1. 종합 판정

Mindily는 감정 일기에서 감정 분석, 자기 확인, 힐링 활동으로 이어지는 흐름이 분명한 **KcELECTRA 연동 MVP**다. 화면 콘셉트와 핵심 입력·분석·저장 흐름은 구현되어 있어 시연 가능한 수준이다. 다만 현재 상태는 팀미션의 최종 서비스라기보다 모델 연결과 UI 흐름을 검증한 1차 결과에 가깝다. 외부 배포, 5명 사용자 검증, Agent·RAG·장기기억이 빠져 있어 “AI 기반 서비스 완성”이라는 평가 기준에는 아직 증거가 부족하다.

## 2. 잘한 점

### 문제와 UX

- 사용자가 자유롭게 일기를 쓰고 모델 결과를 확인한 뒤 직접 감정을 수정할 수 있다.
- 모델 예측과 사용자가 확인한 감정을 분리해, AI가 사용자의 감정을 대신 결정하지 않는다.
- 따뜻한 배경, 둥근 카드, 짧은 문장, 큰 버튼이 초보 사용자에게 적합하다.
- 실패 시 입력 내용을 보존하고, 모델 오류를 숨기지 않는 흐름을 갖췄다.

### 기술과 검증

- 공개 모델의 revision을 고정해 결과 재현성을 높였다.
- 긴 글을 청크로 나누고 토큰 가중 평균을 적용했다.
- 정상 입력, 빈 입력, 잘못된 스트레스 값, 긴 입력을 API 테스트로 확인했다.
- 실제 브라우저에서 감정 변경과 새로고침 후 저장을 검증했다.

## 3. 개선이 필요한 점

### 미션 충족도

현재 체크리스트에서 가장 큰 빈칸은 외부 HTTPS 배포, 실제 사용자 5명 테스트, Agent·RAG·장기기억이다. 이 세 가지가 없으면 발표에서 “구현했다”는 설명과 “실제로 사용되고 검증됐다”는 증거가 분리된다. GitHub 원격 push가 완료되지 않은 상태도 제출 증빙의 약점이다.

### AI 품질

KcELECTRA의 대표 감정과 점수를 보여주지만, 점수가 사용자의 심리 상태의 정확도나 스트레스 수준을 의미하지는 않는다. 현재 모델 출력과 스트레스 1~5 입력이 어떻게 추천으로 변환되는지 규칙이 충분히 설명되지 않았다. 또한 사용자의 문맥을 반영한 공감 대화는 템플릿에 가깝다.

### Agent·RAG·기억

`analyze_emotion`, `recommend_healing`, `save_user_feedback`는 계약으로 정의됐지만 실제 호출 로그와 구현 증거가 없다. 추천 콘텐츠의 출처·갱신일·저작권 상태가 없으면 RAG를 붙여도 신뢰성을 설명하기 어렵다. 장기기억은 감정 원문과 위치 정보가 섞일 위험이 있으므로 동의, 조회, 수정, 삭제를 별도 기능으로 설계해야 한다.

### UX와 접근성

파스텔 색상은 분위기에 잘 맞지만 작은 글자와 낮은 대비가 생길 수 있다. 색만으로 감정을 구분하면 색각 이상 사용자가 의미를 놓친다. 감정 아이콘에는 텍스트 라벨과 패턴을 함께 제공하고, 키보드 포커스·스크린 리더 레이블·44px 이상 터치 영역을 실제 배포 화면에서 다시 확인해야 한다.

### 위치·추천 기능

근처 러닝 장소와 맛집은 유용하지만 위치 권한, 영업시간, 광고성 추천, 안전 문제가 발생한다. 위치 권한을 거부해도 서비스가 동작해야 하며, 장소 카드는 거리·출처·마지막 확인일을 표시해야 한다. 향수 추천은 알레르기와 임산부 등 민감 사용자를 고려해 무향 대안을 제공해야 한다.

## 4. 우선순위별 향후 방향

### P0: 제출 가능 상태 만들기

1. Docker로 HTTPS 배포하고 `/api/health` 공개 확인
2. 팀원 3명의 이름·기여 커밋·회의 기록을 `TEAM_ROLES.md`에 입력
3. 사용자 5명에게 같은 시나리오를 실행시키고 설문과 동의를 익명 보관
4. 사용성 문제를 심각도별로 분류하고 최소 3개를 수정한 뒤 전후 캡처 작성
5. GitHub `main` push와 최종 커밋 링크 확보

### P1: 팀미션의 AI 요구 충족

1. Agent가 `analyze_emotion` 결과를 읽고 `recommend_healing`을 선택하게 한다.
2. 추천 카드마다 출처·저작권·갱신일을 포함한 RAG 문서를 연결한다.
3. `save_user_feedback`는 원문 대신 카드 ID, 도움됨, 짧은 의견만 저장한다.
4. 장기기억은 선택적 동의, 조회, 삭제, 보존기간 만료를 구현한다.
5. Agent가 위기 표현을 감지하면 진단하지 않고 안전 안내와 전문기관 도움을 권한다.

### P2: 추천 서비스 확장

꽃·나무·향수와 필사·음악·취미 추천을 먼저 출시하고, 위치 기반 장소 추천은 이후에 추가한다. 추천 품질은 “정확한 감정” 하나로 평가하지 말고 클릭률, 완료율, 도움됨 비율, 다시 사용 의향으로 측정한다.

## 5. 사용자 테스트 질문

5명 모두에게 다음을 동일하게 묻는다.

1. 일기 작성부터 결과 확인까지 막히는 단계가 있었나요?
2. AI 분석이 내 감정을 이해했다고 느꼈나요? (1~5)
3. 추천 활동을 실제로 해보고 싶었나요? (1~5)
4. 글자·색상·버튼을 읽고 누르기 쉬웠나요? (1~5)
5. 가장 먼저 바꾸고 싶은 기능은 무엇인가요?

## 6. 최종 판단 기준

다음 네 조건을 모두 채우면 최종 제출 수준으로 판단한다.

- 배포 URL에서 핵심 흐름이 재현된다.
- 5명 테스트의 정량 결과와 개선 전후가 있다.
- Agent·RAG·기억 기능이 실행 로그와 함께 설명된다.
- 개인정보·저작권·위치 권한 처리와 한계가 화면과 문서에 표시된다.

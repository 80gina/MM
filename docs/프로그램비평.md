# Mindily 프로그램 비평 및 향후 방향

## 1. 종합 판정

Mindily는 감정 일기에서 감정 분석, 자기 확인, 힐링 활동으로 이어지는 **KcELECTRA 연동 MVP**다. 제한된 의도 판별 Agent, 출처 검색형 추천, 동의 기반 선호 활동 기억·삭제를 구현했다. 무료 임시 HTTPS 접속도 검증했다. 그러나 실제 사용자 5명 검증과 피드백 반영이 없어 팀미션 최종 완료 증거는 부족하다. 상시 배포와 LLM 기반 RAG도 아직 없다.

## 2. 잘한 점

### 문제와 UX

- 사용자가 자유롭게 일기를 쓰고 모델 결과를 확인한 뒤 직접 감정을 수정할 수 있다.
- 모델 예측과 사용자가 확인한 감정을 분리해, AI가 사용자의 감정을 대신 결정하지 않는다.
- 따뜻한 배경, 둥근 카드, 짧은 문장, 큰 버튼이 초보 사용자에게 적합하다.
- 실패 시 입력 내용을 보존하고, 모델 오류를 숨기지 않는 흐름을 갖췄다.

### 기술과 검증

- 공개 모델의 revision을 고정해 결과 재현성을 높였다.
- 긴 글을 청크로 나누고 토큰 가중 평균을 적용했다.
- 정상 입력, 빈 입력, 잘못된 스트레스 값, 긴 입력을 API 테스트로 확인했다.
- 실제 브라우저에서 감정 변경과 새로고침 후 저장을 검증했다.

## 3. 개선이 필요한 점

### 미션 충족도

가장 큰 빈칸은 실제 사용자 5명 테스트와 피드백 반영이다. 임시 HTTPS 주소는 외부 접속을 보여주지만 PC·서버·터널이 꺼지면 사라지므로 안정적 운영의 증거가 아니다. GitHub 코드와 합성 문장 자체 점검을 실사용 검증으로 표현하면 안 된다.

### AI 품질

KcELECTRA의 대표 감정과 점수를 보여주지만, 점수가 사용자의 심리 상태의 정확도나 스트레스 수준을 의미하지는 않는다. 현재 모델 출력과 스트레스 1~5 입력이 어떻게 추천으로 변환되는지 규칙이 충분히 설명되지 않았다. 또한 사용자의 문맥을 반영한 공감 대화는 템플릿에 가깝다.

### Agent·RAG·기억

Agent는 일기에서 `analyze_emotion → recommend_healing`을 호출하고, 대화의 휴식 요청에는 추천만 호출한다. 코치 문장은 규칙 기반이며 자유 생성형 대화가 아니다. 의도 판별이 키워드 중심이라 표현이 다양해지면 잘못 분기할 수 있다. 활동 카드의 NHS·WHO 링크는 출처 검색형 추천이지만, 근거를 LLM 생성 응답에 넣는 RAG는 아니다. 선호 기억은 재시작 후에도 유지되고 삭제·30일 만료 테스트를 통과했다. 다만 브라우저 토큰 분실 시 즉시 삭제할 수 없고, 만료 정리는 다음 기억 요청 때 실행된다.

### UX와 접근성

파스텔 색상은 분위기에 잘 맞지만 작은 글자와 낮은 대비가 생길 수 있다. 색만으로 감정을 구분하면 색각 이상 사용자가 의미를 놓친다. 감정 아이콘에는 텍스트 라벨과 패턴을 함께 제공하고, 키보드 포커스·스크린 리더 레이블·44px 이상 터치 영역을 실제 배포 화면에서 다시 확인해야 한다.

### 배포와 시연의 정확성

도구 호출형 코치를 추가할 때 Dockerfile에 `coach_agent.py`가 빠져 컨테이너에서 서버 import가 실패할 수 있었다. 파일을 포함하고 로컬 import 목록을 검사하는 `test_packaging.py`를 추가했지만, 이 컴퓨터에는 Docker가 없어 실제 이미지 빌드는 아직 확인하지 못했다. 시연 문서가 한때 음악 재생·호흡 일시정지·월간 분석을 구현된 기능처럼 나열한 점도 수정했다. 현재 감정 정리 3문항은 실제로 저장되지만 음악 재생과 실제 주간·월간 패턴은 예시 화면이다.

### 위치·추천 기능

근처 러닝 장소와 맛집은 유용하지만 위치 권한, 영업시간, 광고성 추천, 안전 문제가 발생한다. 위치 권한을 거부해도 서비스가 동작해야 하며, 장소 카드는 거리·출처·마지막 확인일을 표시해야 한다. 향수 추천은 알레르기와 임산부 등 민감 사용자를 고려해 무향 대안을 제공해야 한다.

## 4. 우선순위별 향후 방향

### P0: 제출 가능 상태 만들기

1. Quick Tunnel 주소를 매 테스트 직전에 모바일 데이터로 확인하고, 장기 운영이 필요하면 영속 저장소가 있는 HTTPS 호스팅을 확보한다.
2. 팀원 3명의 이름·기여 커밋·회의 기록을 `TEAM_ROLES.md`에 입력
3. 사용자 5명에게 같은 시나리오를 실행시키고 설문과 동의를 익명 보관
4. 발견된 사용성 문제를 심각도별로 분류하고 우선순위가 높은 문제를 수정한 뒤 전후 캡처 작성. 문제가 3개 미만이면 없는 문제를 만들지 않는다.
5. GitHub `main` push와 최종 커밋 링크 확보

### P1: 팀미션의 AI 요구 충족

1. 현재 키워드 의도 판별을 실제 테스트 발화로 점검하고, 감정 정보가 없는 휴식 요청에서 감정을 단정하지 않도록 유지한다.
2. LLM 기반 RAG를 추가한다면 추천 자료마다 출처·저작권·갱신일을 검증하고 생성 응답이 자료 범위를 벗어나지 않는지 평가한다.
3. `save_user_feedback`의 익명 응답 수와 실제 참가자 수를 구분해 보고한다.
4. 브라우저 토큰 분실 시 개인정보 처리 절차와 정기 만료 정리를 운영 설계에 추가한다.
5. 위기 표현이 들어오면 일반 추천보다 안전 안내를 우선하는 별도 검증을 한다.

### P2: 추천 서비스 확장

꽃·나무·필사·음악 검색·취미 카드는 현재 출처 링크와 함께 추가했다. 향수는 알레르기·무향 대안 설계가 필요해 보류했고, 위치 기반 장소·맛집은 권한·최신 영업 정보·지도 약관을 검증한 뒤 추가한다. 추천 품질은 “정확한 감정” 하나로 평가하지 말고 클릭률, 완료율, 도움됨 비율, 다시 사용 의향으로 측정한다.

## 5. 사용자 테스트 질문

5명 모두에게 다음을 동일하게 묻는다.

1. 일기 작성부터 결과 확인까지 막히는 단계가 있었나요?
2. AI 분석이 내 감정을 이해했다고 느꼈나요? (1~5)
3. 추천 활동을 실제로 해보고 싶었나요? (1~5)
4. 글자·색상·버튼을 읽고 누르기 쉬웠나요? (1~5)
5. 가장 먼저 바꾸고 싶은 기능은 무엇인가요?

## 6. 최종 판단 기준

다음 네 조건을 모두 채우면 최종 제출 수준으로 판단한다.

- 배포 URL에서 핵심 흐름이 재현된다.
- 5명 테스트의 정량 결과와 개선 전후가 있다.
- Agent·기억 두 기술 요소가 실행 로그와 함께 설명되고, RAG 미구현 범위가 명확히 표시된다.
- 개인정보·저작권·위치 권한 처리와 한계가 화면과 문서에 표시된다.
